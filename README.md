# NOVA Dental Studio

Modern dental clinic operations system built with Next.js 14 (App Router), React, TypeScript, Tailwind CSS, shadcn/ui patterns, and Supabase.

> **Notice:** This is a demo portfolio project. All notifications shown in the app are internal simulations. Payment is made at the clinic cashier. WhatsApp, SMS, email, and external messaging are **not connected**.

## ✨ Feature Overview

### 🦷 Patient Management
- Register and view patient records.
- View assigned appointments and medical history.
- Search patients by name, email, or phone.

### 📅 Appointment Scheduling
- Seven-step booking wizard (Service → Dentist → Date → Time → Patient Info → Review → Confirm).
- Real-time availability based on the dentist's schedule and service duration.
- Server-side double-booking prevention (GiST exclusion constraint + unique index).
- Guest (anonymous) booking — no authentication required.

### 🔐 Role-Based Access
- **Doctor (دكتور)** — Signs in via Supabase Auth. Views only their own appointments and patients. Starts and ends their own live sessions. Sees their internal notifications. Cannot manage all doctors, services, schedules, or clinic settings.
- **Secretary (سكرتيرة)** — Signs in via Supabase Auth. Full operational access: manages all appointments, patients, doctors, services, schedules. Uses Smart Appointment Automation. Manages internal notifications and operational analytics.

### 💊 Live Sessions
- Chair-side timer for active appointments.
- Start / End session with automatic status updates.
- Session duration persisted to the database.

### 🧠 Smart Appointment Automation
- Auto-adjusts schedules when slots conflict.
- Blocks unavailable times (breaks, blocked times, overlapping appointments).
- Enforces `max_appointments` per day from schedule settings.
- Auto-notifies staff when a new booking arrives.

### 🔔 Internal Notifications
- All notifications shown in-app are **internal simulations** generated by the system.
- New appointment bookings trigger internal notifications for staff.
- Mark as read / dismiss functionality (persisted to Supabase).

### 🌓 Theme & Internationalization
- Light mode (default) / Dark mode with system-aware detection and persistence.
- English (LTR) / Arabic (RTL) with full bilingual support.
- Default language: **Arabic**. Default theme: **Light**.

### 📱 Responsive Design
- Desktop, tablet, and mobile layouts.
- Collapsible sidebar with RTL-aware positioning.

## 🚀 Setup Instructions

### Prerequisites
- Node.js 18+
- npm
- A Supabase project

### 1. Clone & Install
```bash
# Install dependencies
npm install
```

### 2. Environment Variables
Copy `.env.example` to `.env.local` and fill in your Supabase credentials:

```
NEXT_PUBLIC_SUPABASE_URL=your-supabase-project-url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

> **Never expose your `SUPABASE_SERVICE_ROLE_KEY` in client-side code.** This project uses the anon key with Row Level Security (RLS) for all data access.

### 3. Supabase Setup
1. Create a new Supabase project at [supabase.com](https://supabase.com).
2. Run the migrations in order in the **SQL Editor**:
   - `database/supabase/migrations/001-nova-dental-schema.sql`
   - `database/supabase/migrations/002-add-missing-tables-columns-constraints.sql`
   - `database/supabase/migrations/003-enable-guest-booking-and-roles.sql`
   - `database/supabase/migrations/004-role-scoped-rls-policies.sql`
   - `database/supabase/migrations/005-demo-data.sql`
3. Ensure the `anon` key has `SELECT`, `INSERT`, `UPDATE`, `DELETE` permissions as defined by RLS policies.
4. The `book_appointment` and `get_available_slots` RPCs are granted to `anon`, `authenticated`, and `service_role`.

### 4. Run the App
```bash
# Development server
npm run dev

# Type check
npx tsc --noEmit

# Lint
npm run lint

# Production build
npm run build
```

## 🔄 Seed and Reset Instructions

### Reset the database
1. Open Supabase SQL Editor.
2. Run in order:
   ```sql
   -- Disable RLS temporarily to reset
   ALTER TABLE appointments DISABLE ROW LEVEL SECURITY;
   -- (repeat for all tables)
   -- Delete all data
   DELETE FROM notifications;
   DELETE FROM appointment_history;
   DELETE FROM live_dental_sessions;
   DELETE FROM appointments;
   DELETE FROM schedules;
   DELETE FROM blocked_times;
   DELETE FROM patients;
   DELETE FROM dentists;
   DELETE FROM profiles;
   DELETE FROM services;
   DELETE FROM gallery_images;
   -- Re-enable RLS
   ALTER TABLE appointments ENABLE ROW LEVEL SECURITY;
   ```
3. Re-run migrations 001 → 005 in order.

### Re-seed demo data
Run only `005-demo-data.sql` after 001–004 are applied. It is idempotent and will not duplicate existing records.

## 📖 Feature Explanations

### ⏱️ Live Session Timer
The **SessionTimer** component starts when a doctor clicks "Start Session" on a pending appointment. It:
1. Calls `startLiveSession(appointmentId)` — a server action that creates a `live_dental_sessions` record with status `active` and updates the appointment status to `in-progress`.
2. Shows a running timer on the chair-side card.
3. When the doctor clicks "End Session", `endLiveSession(sessionId)` marks the session `completed`, sets the appointment to `completed`, and writes an entry to `appointment_history`.
4. The session duration is persisted to the database and survives page refreshes.

### 🧠 Smart Appointment Automation
The `get_available_slots` RPC (server-side, SECURITY DEFINER) handles the intelligent scheduling:
- **Slot generation**: Creates time slots based on `clinic_settings.slot_duration` (default 30 min) and the service's `duration_minutes`.
- **Breaks**: Excludes slots falling within the dentist's daily break time (default 13:00–14:00).
- **Blocked times**: Excludes slots in `blocked_times` records (leave, admin blocks).
- **Overlap prevention**: Excludes slots overlapping existing non-cancelled appointments.
- **Daily cap**: Enforces `max_appointments` from the schedule record (default 8/day).
- **Past-time guard**: Rejects slots that have already started today.

### 🔔 Internal Notifications (Simulations)
All notifications displayed in the app are **internal system simulations**:
- The `book_appointment` RPC creates an internal notification with `type: 'appointment'` and `user_id: NULL` (clinic-wide).
- Staff can view, mark as read, and dismiss notifications.
- Mark-as-read and dismiss actions persist to Supabase via server actions.
- **No external messaging** (WhatsApp, SMS, email) is integrated. All notifications remain within the app.

### 💳 Payment
Payment is **not handled** by this system. All appointment bookings note that **"Payment is made at the clinic cashier"**. No online payment gateway, invoice generation, or billing automation is connected.

### 📱 Responsive Layout
- **Desktop**: Full sidebar + header + content layout.
- **Tablet**: Collapsible sidebar; content adjusts to available width.
- **Mobile**: Sidebar hidden by default; toggle button shows it as an overlay. Content uses full-width cards and stacked layouts.

## ☁️ Deployment (Vercel)

1. Import the GitHub repo into Vercel (framework is detected as Next.js).
2. Optional environment variables — the site runs without them in demo mode:
   - `NEXT_PUBLIC_APP_URL` — the canonical domain (used by OG/canonical/sitemap).
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` — enables real
     booking + staff sign-in. Without them every public page still works and the
     booking flow explicitly says the appointment was simulated.
3. Build command `npm run build`, output is handled automatically.

Deployment notes:

- `X-Frame-Options` is intentionally not sent, and CSP `frame-ancestors` allows the
  preview/embedding hosts, so the site can be embedded in preview iframes.
- `robots.ts` disallows staff routes (`/dashboard`, `/patients`, …) while
  `sitemap.ts` lists only public pages.
- Images are generated/served locally from `public/`, so no external image host is
  required.
